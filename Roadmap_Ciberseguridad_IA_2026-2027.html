Hoja de ruta 2027

Proyectos 2027 que materializan la evolución del rol

Todos corren sobre Ollama (modelo open-source autoalojado, p. ej. Llama 3.1 8B) como motor de razonamiento, orquestado por n8n y Python — sin enviar datos a IA en la nube. El objetivo es ver más y alertar antes, no remediar. Catálogo completo para elegir — 4 recomendados en detalle en el siguiente apartado.

01

Control Coverage Testing 2.0

Objetivo: cobertura y alerta continua de EDR/DLP — reemplaza Airflow
Arquitectura
Fuentes — API CrowdStrike Falcon, API REST Netskope
Orquestación — n8n (workflows programados)
Procesamiento / IA — Python + Ollama (Llama 3.1 8B local) clasifica resultado y redacta evidencia mapeada a NIST CSF
Almacenamiento — PostgreSQL / Dataverse como repositorio de evidencia
Alerta / visualización — Power BI (KCI) + Teams webhook ante drift crítico
  • % de controles con cobertura validada / mes
  • MTTA de drift de configuración
  • Horas de evidencia generadas sin intervención manual
95%+
meta de cobertura de controles con validación mensual continua
02

Mapa de cobertura de activos, aplicaciones y bases de datos

Objetivo: saber qué existe y qué está — o no — protegido
Arquitectura
Fuentes de inventario — AWS Resource Explorer, Azure Resource Graph, GCP Asset Inventory, OCI Search, CrowdStrike CSPM/ASPM, catálogo de apps en Dataverse
Orquestación — n8n (barrido periódico multicloud)
Procesamiento / IA — Python correlaciona activo vs. agente EDR vs. cobertura DLP vs. monitoreo de BD; Ollama redacta la narrativa de brechas
Almacenamiento — Dataverse (histórico de cobertura)
Alerta / visualización — Power BI "Coverage Score" + alerta a Teams ante activo nuevo sin cobertura
  • % de activos con cobertura completa (EDR + DLP + monitoreo)
  • N.º de blind spots detectados / mes
  • Tiempo medio de detección de activo no cubierto
0
meta: activos productivos sin cobertura EDR/DLP conocida
03

Agente de Threat Intelligence interno

Objetivo: alertar de vulnerabilidades relevantes para el stack propio, antes que terceros
Arquitectura
Fuentes gratuitas — NVD CVE API, CISA KEV, GitHub Security Advisories, AlienVault OTX, abuse.ch (URLhaus / ThreatFox)
Orquestación — n8n (polling programado de feeds)
Procesamiento / IA — Python cruza CVEs contra el inventario de activos/software del proyecto 2; Ollama redacta la alerta priorizada con contexto ("afecta a tu activo público X")
Almacenamiento — Dataverse (histórico de alertas y triage)
Alerta / visualización — Teams / correo + KCI en Power BI
  • Tiempo medio entre publicación de CVE y alerta interna (MTTA)
  • % de CVEs triados automáticamente por relevancia
  • N.º de vulnerabilidades críticas aplicables detectadas / mes
Horas, no semanas
meta: tiempo entre CVE público y alerta ante un activo propio afectado
04

Evaluador de dominios y superficie de ataque externa

Objetivo: vigilar dominios propios y detectar typosquatting/phishing, apoyado en la gestión ya existente de SSL y Cloudflare
Arquitectura
Fuentes gratuitas — crt.sh (certificate transparency), dnstwist (open-source, genera variantes typosquat), urlscan.io, VirusTotal (API community), Shodan (free tier), WHOIS/RDAP, SSL Labs API
Orquestación — n8n (barrido diario)
Procesamiento / IA — Python + dnstwist genera variantes de dominio; VirusTotal/urlscan las puntúa; Ollama prioriza y redacta el reporte de riesgo
Almacenamiento — Dataverse (histórico de dominios vigilados)
Alerta / visualización — Power BI "Domain Risk Score" + alerta inmediata ante dominio sospechoso activo o certificado próximo a expirar
  • N.º de dominios sospechosos / typosquat detectados por mes
  • Días de anticipación a expiración de certificados SSL
  • % de dominios propios con grado SSL A/A+
Detección temprana
meta: identificar dominio fraudulento antes de una campaña de phishing activa
05

Shadow AI Discovery & Governance

Objetivo: visibilidad de qué herramientas de IA usa la organización, antes de que se conviertan en fuga de datos
Arquitectura
Fuentes — logs CASB/DLP de Netskope (categoría apps de IA), Microsoft Graph (uso de Copilot/M365), logs de Cloudflare Gateway
Orquestación — n8n (agregación periódica de tráfico y eventos DLP)
Procesamiento / IA — Python clasifica dominios/apps de IA contra un catálogo curado; Ollama redacta el riesgo por app y por área de negocio
Almacenamiento — Dataverse (registro histórico de apps de IA detectadas)
Alerta / visualización — Power BI "Shadow AI Risk Score" + Teams si una app de IA no aprobada mueve datos sensibles
  • N.º de apps de IA no autorizadas detectadas / mes
  • % de tráfico hacia apps de IA con política DLP aplicada
  • Cobertura de política de uso de IA por área
Visibilidad total
meta: inventario vivo de toda app de IA usada en la organización
06

Visibilidad DevSecOps: SBOM, secretos y dependencias

Objetivo: saber qué corre dentro de cada aplicación, no solo qué la rodea
Arquitectura
Fuentes — CrowdStrike ASPM, API de GitHub/GitLab, Trivy (escaneo de vulnerabilidades open-source), Syft (generación de SBOM), Gitleaks (secretos expuestos)
Orquestación — n8n dispara el escaneo por repositorio, en pipeline o de forma periódica
Procesamiento / IA — Python consolida los hallazgos de los scanners; Ollama los correlaciona con la criticidad de negocio del aplicativo (catálogo del proyecto 2) y redacta el riesgo real por app
Almacenamiento — Dataverse (histórico de SBOM y hallazgos)
Alerta / visualización — Power BI + alerta inmediata ante secreto expuesto o dependencia crítica sin parchear
  • % de aplicaciones con SBOM vigente
  • N.º de secretos expuestos detectados / mes
  • Tiempo medio de exposición de un secreto hasta la alerta
100%
meta: aplicaciones críticas con SBOM e inventario de dependencias vigente
07

Gobernanza y red-teaming de agentes de IA internos

Objetivo: asegurar los propios agentes construidos en n8n/Ollama antes de que alguien más lo haga
Arquitectura
Fuentes — registro interno de workflows n8n activos, logs de Ollama, catálogo de agentes en Dataverse
Orquestación — n8n ejecuta una batería programada de pruebas de red-team (prompt injection, fuga de datos, escalamiento de permisos) contra cada agente
Procesamiento / IA — Python corre los payloads de prueba alineados a OWASP Top 10 for LLM Applications; Ollama actúa como juez, evaluando si el agente filtró datos o fue manipulado
Almacenamiento — Dataverse (hallazgos por agente y versión)
Alerta / visualización — Power BI "AI Agent Risk Score" + alerta si un agente falla una prueba crítica
  • % de agentes de IA con evaluación de seguridad vigente
  • % de pruebas OWASP LLM superadas por agente
  • Tiempo medio de detección de un agente mal configurado
0
meta: agentes de IA en producción sin evaluación de seguridad
08

Radar de herramientas de seguridad open-source

Objetivo: vigilar, evaluar y operacionalizar herramientas nuevas de GitHub/comunidad antes que la competencia o un atacante
Arquitectura
Fuentes — GitHub API (trending, releases, topics security-tools/osint/dns/phishing), GitHub Security Advisories, RSS de boletines (tl;dr sec, r/netsec)
Orquestación — n8n (polling programado + triggers por release)
Procesamiento / IA — Python + Ollama clasifica README y metadata (categoría, madurez, relevancia, riesgo); sandbox Docker efímero para prueba controlada
Almacenamiento — Dataverse (catálogo de herramientas evaluadas)
Alerta / visualización — Power BI "Tooling Radar" + Teams ante herramienta de alta relevancia
  • Tiempo medio de triage de una herramienta relevante
  • % de herramientas evaluadas que terminan integradas al stack
  • N.º de herramientas evaluadas / mes
< 5 días
meta: tiempo entre publicación de herramienta relevante y su evaluación
09

Exposición de correo y phishing de marca

Objetivo: visibilidad de la postura de correo del dominio propio y detección de phishing que suplanta la marca
Arquitectura
Fuentes — verificación DNS (SPF/DKIM/DMARC), Have I Been Pwned API (correos corporativos expuestos en brechas), PhishTank y OpenPhish (feeds de phishing), Netskope (correlación de tráfico bloqueado)
Orquestación — n8n (barrido diario)
Procesamiento / IA — Python valida configuración SPF/DKIM/DMARC; Ollama redacta el riesgo y prioriza para coordinación con el equipo de correo
Almacenamiento — Dataverse
Alerta / visualización — Power BI "Email Exposure Score" + alerta ante credencial corporativa filtrada o campaña de phishing con marca propia activa
  • % de dominios propios con DMARC en enforcement
  • N.º de credenciales corporativas expuestas detectadas / mes
  • N.º de campañas de phishing con marca propia detectadas
100%
meta: dominios de correo propios con SPF/DKIM/DMARC verificado
10

Visibilidad de identidad y postura SaaS (SSPM)

Objetivo: visibilidad de accesos, permisos OAuth y cuentas de riesgo dentro del perímetro que ya administras en Microsoft 365
Arquitectura
Fuentes — Microsoft Graph API (Identity Protection, consentimientos OAuth de apps de terceros, señales de riesgo de sign-in), Splunk (correlación)
Orquestación — n8n (barrido periódico + trigger ante nuevo consentimiento OAuth)
Procesamiento / IA — Python detecta apps con permisos excesivos, cuentas sin MFA, sign-ins anómalos; Ollama prioriza y redacta el hallazgo
Almacenamiento — Dataverse
Alerta / visualización — Power BI "Identity Exposure Score" + Teams ante app de terceros con permisos de alto riesgo recién autorizada
  • % de cuentas con MFA activo
  • N.º de apps OAuth de alto riesgo detectadas
  • N.º de cuentas privilegiadas sin actividad reciente (stale)
0
meta: apps OAuth de alto riesgo sin revisar

Evolución profesional

De especialista de herramientas a líder de Cybersecurity Engineering & Controls

La evolución propuesta no compite con Security Architecture: complementa ese rol desde el frente tecnológico, llevando estándares y requisitos a controles implementables, automatizados, medibles y continuamente verificables.

2025 · Base

Especialista de herramientas

Operación y administración de CrowdStrike, Netskope, Microsoft, cloud y controles de seguridad; foco en cobertura, configuración y atención de hallazgos.

2026 · Evolución

Security Controls + Automation

Integración por API, Graph, n8n, Python, Dataverse y Power BI; automatización de indicadores y pruebas de controles sobre el stack existente.

2027 · Rol objetivo

Cybersecurity Engineering & Controls Lead

Diseño de capacidades transversales de control continuo, visibilidad, exposición, inteligencia y automatización; arquitectura de soluciones de seguridad.

Siguiente etapa

Lo que papa Dios diga

Liderazgo de equipo y portafolio: estrategia técnica, priorización, capacidades de ingeniería, métricas ejecutivas y evolución de la función.

Qué cambia: de administrar herramientas a diseñar mecanismos de seguridad; de generar reportes a construir inteligencia; de revisar controles periódicamente a validarlos continuamente; de integrar productos de forma aislada a construir una capa tecnológica común sobre APIs, automatización y datos.

Encaje organizacional: Security Architecture define principios, estándares y arquitectura objetivo; Cybersecurity Engineering & Controls convierte esos lineamientos en capacidades técnicas, controles automatizados, evidencia y monitoreo continuo; Security Operations ejecuta y responde sobre la operación diaria.

"El objetivo del siguiente rol no es administrar más herramientas; es diseñar cómo la organización obtiene visibilidad, prueba sus controles y convierte datos de seguridad en decisiones."
